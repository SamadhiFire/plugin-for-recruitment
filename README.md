# 求职简历助手

本地运行的 Chrome/Edge 填表 Agent。选择简历方向后，点击“分析当前页面”，内部完成字段理解、记录匹配、内容复核与冲突检查；最终统一确认后自动补齐记录并填入。不会自动点击保存、下一步、附件上传或最终提交。

0.9.3 优先避免遗漏和误覆盖：扫描时会先用招聘站点的“添加”按钮补齐教育、实习和项目空白记录，再读取真实字段模板；明确是同一条经历时修正原记录，身份含糊时保留旧条目。日期控件按原生、Ant Design、Arco、Element、Semi、腾讯输入框和字节 Universe Design 分别提交并回读校验。千问超时或漏回字段时，精确主库映射会由本地严格校验接管，最后只需检查未知字段和冲突记录。详细流程见 [AGENT-NOTES.md](AGENT-NOTES.md)。

0.9.4 精简侧栏：准备阶段只保留方向和分析入口，岗位要求按需展开；待补充字段按经历分组，点开编辑；详细原因与工具默认收起，确认操作固定在底部。

0.9.7 修复滴滴样式表单的字段标签、分区和拆分年月识别。实习、项目等重复记录按每条经历生成方案；使用拆分年月控件时需要同步重启 0.9.7 本地服务。代码层面覆盖滴滴样式表单，真实页面仍待 Chrome 调试连接恢复后验证。

0.9.8 更新简历方向选择器：使用自定义单选菜单展示四条投递主线，并在选中后显示匹配岗位与慎投边界；避免系统下拉菜单遮挡方向建议卡。

0.9.9 修复双语“+ 添加 / Add”经历入口、数值式年月标签，并在分析结果中直接显示教育、实习、项目记录的覆盖数量。页面只提供按钮而没有记录字段时，现有实现会在分析阶段先新增空白记录以读取真实字段结构；招聘网站若自动保存，空白记录也可能被网站保存。请在最终提交前检查这些记录。

0.9.10 在宝洁申请页真实 DOM 上定位并修复长说明使实习区块标题被过滤、已选年份/月数字被误当字段名的问题。验证了页面存在教育、实习、工作、项目四个独立“添加”入口；未触发网站新增、保存或提交，实际填入仍需重新加载扩展后验证。

0.9.11 再次读取宝洁申请页实际记录结构，修复单条实习或项目内各字段被拆成多条记录、导致日期和经历串填且漏增其余两条的问题。当前页实测教育 3 条、实习 1 条、项目 1 条；本地回归验证可将实习与项目各补至 3 条。已有错误日期需在新版预览中核对并修正。

升级到 0.9.11 时，请先关闭旧助手的命令行窗口，再双击 [启动助手.cmd](启动助手.cmd)。浏览器若加载的是本项目 `extension` 目录，前往 Edge 扩展管理页点击该扩展的“重新加载”；若使用压缩包，请重新解压 0.9.11 包后加载解压目录。确认 `http://127.0.0.1:8787/api/health` 返回 `"version":"0.9.11"`，再刷新招聘页面、重新生成预览，重点核对已有记录的日期与其余两段实习、两段项目。

## 已实现

- Chrome/Edge Manifest V3 侧边栏扩展；包含 OPPO、字节跳动、小米、VIVO、腾讯、京东等站点适配规则，并可在用户主动点击扩展后动态识别其他招聘网站。本次已在用户现有 Chrome 中验证字节和腾讯的空记录新增与真实字段结构。
- 填表前必须选择简历方向；当前提供“AI产品｜应用与商业化”“AIGC产品｜内容与创作”“AI解决方案｜售前与商业化”“产品市场｜GTM与增长”四种已就绪方向。各方向会展示推荐岗位与慎投边界，且不会回退或覆盖其他方向。
- 不依赖截图：内容脚本读取 `input`、`textarea`、`select`、`contenteditable` 等真实表单元素，并派发网页框架需要的 `input/change/blur` 事件。
- 规则只产生内部候选，不再直接决定自动填写。所有可处理字段（包括已有规则匹配和已有内容的字段）经过千问理解、独立复核提示词与本地约束校验；不是只给未知字段补漏。旧的“规则匹配”“千问补充识别”按钮已合并为自动分析入口。
- 侧边栏常驻时会监听当前标签页：切换公司或页面跳转后，立即清空上一页计划与单字段草稿；重新选择方向（如需）并点击右上角刷新图标后识别。
- 首次进入尚未授权的新招聘域名时，点击右上角刷新图标，浏览器会请求该域名的页面访问权限；授权一次后，之后刷新该官网无需重复授权。
- 填写过程中如果 React/Vue 页面重渲染导致旧 DOM 失效，会依据区块、记录序号、语义键、标签和控件类型重新定位并继续填写。
- 对未知官网采用通用的重复兄弟容器识别，可覆盖常见教育、实习、项目卡片；空白选填字段也会交给千问判断，无法从主库确认的内容仍保持“待确认”。
- 分析阶段会先为完全空白的经历区块添加必要的空记录，读取真实字段结构；已有字段模板的缺失记录则依据模板生成预览。最终确认后自动补齐余下记录、核对新字段与预览的一致性并填入。没有模板、添加后未出现字段或新控件与模板不同，会保留异常提示，不连续盲点、不猜测填入。
- 教育、实习、项目优先按身份及日期/学历/职位匹配。同一条经历的旧正文直接更新，不因为文案不同就重复新增。已有空白条目优先复用；身份冲突、同名重复或疑似其他经历则保留原项并另行补齐，供最后删查。
- 经内部复核及校验的内容默认勾选、折叠展示，包含有事实依据且经复核的开放题文案。规则误判会在内部修正；长度、选项、记录或事实约束未通过的内容单独展示。模型不可用时，未经复核的规则候选不会默认勾选。
- 最终方案汇总拟新增经历、拟修正已有字段与待补充项。执行后回读全部成功字段，未执行、失败和待补充内容继续保留；当前页面未出现的经历区块明确提示尚未填写。
- 页面字段列表显示区块、记录序号、必填/选填、只读状态、控件类型、字数上限和当前值。过滤隐藏模板、禁用字段、密码、验证码与上传/提交等非填写控件；支持包装式 label、原生下拉框显示文本、无 input 的 ARIA combobox 和只读式自定义下拉框。
- 预览后网页内容已被用户修改时停止覆盖；字段消失后不按位置猜测其他控件。切换方向或页面后丢弃迟到的异步方案，防止旧方向内容重新出现。
- 可将简历之外、你已经填写过的补充答案保存到本机 `data/answers.memory.json`；基础信息和语言成绩全局复用，开放题按简历方向隔离。
- 基础简历主库在 [data/resume.profile.json](data/resume.profile.json)，方向目录在 [data/profile-catalog.json](data/profile-catalog.json)，差异内容保存在 `data/profiles/`；侧边栏编辑当前方向时只会保存相对基础库的差异。
- 千问通过本地服务调用；API 密钥只放在 `.env`，扩展代码、浏览器存储和 Git 均不包含密钥。
- 统一使用 AI 产品经理表达策略，并根据具体字段和 JD 自动兼顾产品、增长与商业化重点；固定分点、保留真实指标、不得臆造事实。
- 主库内置常用 AI 工具与模型、AI 协作项目、个人特长、兴趣爱好和自我评价；AIGC方向另含个人优势、自我介绍和应聘动机，可识别不同公司的相似字段。通用版 AI 协作项目提供约 500/800/1000 字三档版本，并按网页字数上限自动选择完整版本；AIGC版当前使用已确认的1000字内完整版，短版将在单独确认后补充。

## 启动

1. 安装 Node.js 20 或以上版本。
2. 双击 [启动助手.cmd](启动助手.cmd)，或在此目录打开 PowerShell，运行：

   ```powershell
   npm run start
   ```

3. 打开 `chrome://extensions` 或 `edge://extensions`，启用“开发人员模式”。
4. 点击“加载已解压的扩展程序”，选择本目录下的 `extension` 文件夹。
5. 打开已登录的招聘页面，点击工具栏中的“求职简历助手”；选择简历方向，点击“分析当前页面”，等待内部分析。按需处理突出显示的少数问题，点击“确认填入”，最后在网页检查增删补查并自行保存。

代码更新后，先关闭旧本地服务并重新启动助手，再在 `chrome://extensions` 或 `edge://extensions` 对本扩展点击一次“重新加载”，最后刷新招聘页面。新版界面会拒绝未经 Agent 复核的旧服务方案。

本地服务必须持续运行。关闭“启动助手”窗口/PowerShell 后，扩展仍可读取页面字段，但无法调用千问或更新磁盘主库。启动脚本会优先识别常见的 Windows Node.js 安装位置（也包含本机的 `D:\Program Files\nodejs\node.exe`）。侧边栏“工具与设置 → 模型设置”可粘贴或替换主 API Key；保存后只会写入本机 `.env`，输入框不会回显密钥，也不需要每次填写。`.env` 可同时配置 `DASHSCOPE_API_KEY_FALLBACK`，主密钥请求失败时自动尝试备用密钥。

## 更新简历

推荐先在侧边栏选择简历方向，再在“工具与设置 → 简历资料”编辑解析后的完整 JSON。每次保存都会递增 `meta.version`，并把差异写入对应的 `data/profiles/*.json`，不会覆盖其他方向。未覆盖字段继续继承基础库 `data/resume.profile.json`。

如果你更新了所有方向共用的客观事实，应同步到 `data/resume.profile.json`；如果只是某个方向的表达、排序或项目选择，应写入对应方向文件。时间、指标、公司/项目名和链接应优先核对，缺少依据的数据保持“待确认”。

## 安全与边界

- 不要把 `.env` 发给他人，也不要提交到 Git；它已经被忽略。
- 验证码、短信验证、登录和附件上传必须手动操作。
- 扩展不会绕过网站限制，不会读取 HttpOnly Cookie，也不会提交你的申请。
- 页面升级后若字段无法识别，可先刷新字段列表；自定义日期选择器、级联下拉框等仍可能需要增加站点适配规则。
- 原生日期/月控件直接填写，不发送回车；自定义日期控件不再用回车确认。不支持的控件会提示手动填写。
- 扩展不点击保存或提交，但招聘网站自身可能在输入或失焦时自动保存；扩展无法保证网站没有自己的自动保存行为。
- 当前扫描仅覆盖顶层文档，iframe 和 Shadow DOM 中的字段尚未支持；模拟 DOM 测试不能替代真实 React/Vue 页面与浏览器权限联调。
- 每批最多 24 个字段，内部按“理解 → 复核”调用两次当前配置的千问模型，因此比旧版仅规则匹配慢、模型调用更多。复核是同一模型的独立提示词调用，不是准确率保证；本次未调用真实模型验证其判断质量。
- 手机号、证件号码等网页基础字段现值不发送给模型；经历身份、字段标题/说明/选项和简历中的非基础事实会用于内部理解。API Key 始终由本地服务保管。

本次调试不需要打开浏览器或调用真实千问接口。测试使用模拟页面和模型响应，不修改简历、答案库或 `.env`。

```powershell
npm ci
npm run check
npm test
```

运行服务要求 Node.js 20+；安装测试依赖建议使用 Node.js 24+（当前 jsdom 要求 20.19+、22.13+ 或 24+）。测试覆盖字段识别、记录对齐、计划确认、异步方向切换、模型故障降级与禁止自动提交相关行为。
